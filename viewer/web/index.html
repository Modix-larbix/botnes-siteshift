        Why SiteShift exists, and what this prototype demonstrates
        
    
        A robot should be able to work toward a goal when its surroundings no longer match its instructions. SiteShift explores a small part of that problem: noticing a change, keeping uncertainty visible, and checking what actually happened. Today, the inspection and gestures are programmed; the robot does not yet make an open-ended plan.
        
    
        
      
        Observe, then act
        The simulated robot opens drawers and checks the zones it can reach. It keeps uncertain areas marked as still to check. Its goal is to find a sponge, pick it up and scrub a bowl.
        
      
        A new physics run
        Play simulation starts MuJoCo on this Mac. The images above are rendered from that run while it computes. The overview is for you, the spectator, and is never passed to the robot.
        
      
        A bounded model choice
        The robot executes fixed programs written by the team. When two next steps are valid, it reuses a recorded NVIDIA Nemotron choice only if the request text matches exactly. There is no live AI call or training here.
        
      
        Check what happened
        Run analysis reads this new episode’s evaluator records. It shows which criteria were met and whether the compared facts match the recorded reference. The hidden-sponge case can end by asking for help.
        
    
        
    
        Scope of this prototype
        Three situations in one development kitchen, with simulated perception and uncalibrated physics. This does not demonstrate general-purpose autonomy or real-world deployment. The recorded studies, report analysis and known limitations are available separately.
